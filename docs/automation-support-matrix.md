# Automation support matrix

Every capability in the demo, classified by how much of it is automated. Rows 1–47 come from the approved plan §3; rows 48 and later come from Revision 2 (plan §9.7), the Phase 3 ADRs, and the implementation phases (rows 63 and later). Lettered rows, such as 15d, add detail to the row they follow. Rows 99 to 110 are reserved for the presentation layer (Phases 18 and 19; 109 and 110 are unused since Phase 19 dropped the org app), rows 111 to 120 for the fast redeploy (Phase 20), rows 121 to 125 for Phase 19b's Insights app, rows 136 to 145 for T4, the PostgreSQL flexible server (Phase 24, [ADR 0019](adr/0019-t4-postgresql-flexible-server.md)), and rows 160 to 169 for Phase 28's one command and guided stop ([ADR 0018](adr/0018-fast-redeploy-parallel-tracks-golden-snapshot.md#amendments-2026-10-29-phase-28-one-command-one-guided-stop)). Since 2026-11-05, rows 173 and 174 are the Insights app in every deployment, rows 175 and 176 the nightly safety stop ([ADR 0024](adr/0024-nightly-safety-stop.md)), and row 15 and rows 177 to 180 T2's default `JumpstartImage` mode and the build modes' evaluation guard. Since 2026-11-06, rows 181 and 182 are a fix pulled during a deployment reaching the VMs, and row 183 the history report's snapshot at the end of every deployment. **Revision 2 changes are marked (R2).**

## Automated vs manual

The scripts automate every step that has a documented interface. Each step that's left is manual for a stated reason, and the scripts report it as **Manual action required** with its exact steps, so nothing is hidden. [What stays manual, and why](#what-stays-manual-and-why) gives each reason with its Microsoft Learn source.

- **Automated:** a script does it, unattended.
- **Manual (one time):** once per tenant, subscription, or environment.
- **Manual (each session):** around each demo session.
- **Presenter-driven:** done live in a product's UI, by design.

"You" is the person who deploys, with Contributor on the subscription. In the **Time** column, a date means measured that day, and ≈ means an estimate.

## Classes

| Class | Meaning |
|---|---|
| **FA**: Fully automated | Runs with no human step under the documented minimum permissions (Contributor on the subscription) |
| **AP**: Automated with prerequisite | Automated once a listed prerequisite (P1–P16) or input is in place |
| **MAN**: Manual | No supported automation exists. The repo validates the result and prints exact steps. |
| **OPT**: Optional | An opt-in capability, presenter-driven, or validated empirically |
| **DEF**: Unsupported or deferred | Not supported by the docs, or deliberately out of scope for v1 |

**P** marks a preview dependency: Copilot, Database Agents, alerts, SQL Server on Azure VM performance monitoring, unified inventory, the Arc SQL monitoring setting, the SQL telemetry endpoint, or Fabric Apps. Database Hub itself (Estate, Performance, security, optimization, and the real-time dashboards for SQL, PostgreSQL, and Cosmos DB) is generally available since 2026-11-17. Prerequisites P1–P16 are defined in [prerequisites](prerequisites.md), P1–P11 first in [ADR 0008](adr/0008-identity-rbac-abac.md). Validation statuses are defined in [ADR 0012](adr/0012-validation-model.md).

## What stays manual, and why

Every manual step reports **Manual action required** with its exact steps, so nothing is hidden. The first group exists only because no supported automation was found; the others are deliberate.

**No supported automation found** (checked against Microsoft Learn, 2026-10-19 to 2026-11-18):

| Step | Row | Why it's manual | Where it's documented |
|---|---|---|---|
| The Hub tenant setting (P4) | 27 | A tenant-wide Fabric administrator setting whose internal name isn't documented ([List Tenant Settings](https://learn.microsoft.com/rest/api/fabric/admin/tenants/list-tenant-settings) can only match it by title) | [Prerequisites](prerequisites.md) |
| The Database Hub UI, its saved views, and monitor templates, including the template wizard shown live next to the dashboard as code | 31a, 33, 34, 104 | Database Hub has no public API, ARM, or Bicep resource; Learn documents these only as portal experiences ([overview](https://learn.microsoft.com/fabric/database/hub/overview)) | [Walkthrough](demo-walkthrough.md) and [presentation surfaces](presentation.md) |
| Copilot in Database Hub and Database Agents, and the record of Copilot's coverage | 35, 35b | No API. Database Agents covers Azure SQL Database only, so T3 ([Database Agents](https://learn.microsoft.com/fabric/database/hub/database-agents)); Copilot's target coverage isn't documented ([FAQ](https://learn.microsoft.com/fabric/database/hub/faq)) | [Agent guide](../fabric/agent/README.md#live-coverage-record) |
| Selecting T3 for Database Agents in **Manage agents** > **Database agent settings**: optional, once per deployment, about 30 seconds, and only the Database Agent loop needs it (`HUB.AGENT.T3`, under **DONE**'s **Please confirm**) | 194 | Database Hub's settings have no API ([enable Database Agents](https://learn.microsoft.com/fabric/database/hub/enable-database-agents)) | [Walkthrough](demo-walkthrough.md#the-database-agent-loop-on-t3) |

**By design: a person approves or responds** (the brief requires human approval before any action):

- Every action Copilot in Database Hub proposes (row 35).
- The response to an issue Database Agents raises on T3, which Run all's Database Agent loop makes itself (row 194).
- The missing-index remediation script (row 75); `reset --undo-remediation` reverts it.

**By design: you sign in** (a repository rule, so no script holds or requests your credentials):

- Signing in to the Azure CLI, once, with `az login` (`--use-device-code` in a codespace or a container). The scripts never sign in, never sign out, and never change the CLI's default subscription: every Azure call names the configured subscription, and the subscription guard checks that subscription's tenant and account before anything is written ([prerequisites](prerequisites.md#target-subscription-configuration-the-subscription-guard)). `init.ps1` then writes the configuration from that sign-in (row 150). On a shared machine, the optional separate Azure CLI profile is also yours to set ([prerequisites](prerequisites.md#optional-a-separate-azure-cli-profile)).
- Signing in the Rayfin CLI, once, as the demo's Fabric user (P14, row 124), for the Insights app, only when Fabric refuses the Azure CLI's token: since 2026-11-09 the app deploys with your `az login` (row 173). After a refusal, `deploy.ps1` starts that sign-in at the beginning of its next run, in a session that can take keyboard input, and you sign in in the browser. Without `-SignIn`, `configure-fabric-app.ps1` only reads the sign-in with `rayfin login status --json` and reports **Manual action required** with the exact command when it's missing; with `-SignIn`, it runs that command in your console (row 152). The CLI's service principal sign-in isn't supported yet ([CLI reference](https://learn.microsoft.com/fabric/apps/cli-reference)). Without the sign-in, `deploy.ps1` still ends **DONE**, and the status page shows the app's row in red (Failed), with the command that adds it.
- Signing in to GitHub for Ask, the Copilot chat in the Insights app: each viewer, once per browser, with GitHub's device flow, on their own GitHub Copilot plan (row 191, [ADR 0028](adr/0028-ask-copilot-in-the-insights-app.md)). In a GitHub organization that restricts OAuth apps, an owner approves **Database Hub Insights Ask** once ([OAuth app access restrictions](https://docs.github.com/organizations/managing-oauth-access-to-your-organizations-data/about-oauth-app-access-restrictions)). Each viewer can revoke it later at [Authorized OAuth Apps](https://github.com/settings/applications), and **Sign out of GitHub** in the chat's account menu clears a browser's sign-in.

**Needs someone with more than Contributor** (the scripts print the exact commands, and `assignRoles` runs them when the caller can):

- Contributor for the GitHub identity (P7), Reader for presenters who aren't Contributors (P8), and the opt-in Key Vault's roles (row 98) ([permissions](permissions.md)).
- The session control's two custom roles and their assignments A1 to A4 (P15, row 127), and the nightly safety stop's custom role and its one assignment (P16, row 176): `deploy.ps1` makes them itself when you may, whatever `assignRoles` says (owner-approved exceptions, ADR 0024 and ADR 0026); otherwise an Owner runs `./scripts/grant-safety-stop.ps1` once, which **DONE** prints and which grants them all ([permissions for the session control](permissions.md#the-on-demand-activity-control) and [for the nightly safety stop](permissions.md#the-nightly-safety-stop)). Until then, nothing stops T4 after its 7-day restart, Run all can't start a session, and T5's container stays between sessions.
- The Fabric tenant settings (P4, P12, P13, row 27, row 174), and the strict content security policy setting for static-hosted Fabric Apps, which stays off for Ask (its default; `ASK.CSP` warns when it's on): a Fabric administrator's.
- Resuming or pausing the Fabric capacity (P5): its administrator's decision, outside the demo's resource group ([cost management](cost-management.md#microsoft-fabric-capacity)). For an F capacity that's yours alone, in the same subscription, `fabric.manageCapacity` lets `start-demo.ps1` resume it and `stop-demo.ps1` pause what it resumed, with Contributor (row 153).

**Manual by choice:**

- Sharing the history report with viewers outside the workspace, and their data access for its Direct Lake model (row 108): both grant permissions to people, and workspace members need neither ([history report](../fabric/powerbi/README.md#sharing-the-report)). Phase 19 creates no app; the Insights app, a Fabric Apps (preview) item built with the Rayfin SDK and CLI, is a separate item (Phase 19b).
- GitHub environments, their secrets, and protection rules (row 46; optional, for maintainers), unless you opt in: with your own GitHub CLI sign-in, `setup-github-oidc.ps1 -ConfigureGitHub` sets them up. Without it, the scripts never write to your GitHub repository, and they print the `gh` commands instead (R283).
