# Automation support matrix

Every capability in the demo, classified by how much of it is automated. Rows 1–47 come from the approved plan §3; rows 48 and later come from Revision 2 (plan §9.7), the Phase 3 ADRs, and the implementation phases (rows 63 and later). Lettered rows, such as 15d, add detail to the row they follow. Rows 99 to 110 are reserved for the presentation layer (Phases 18 and 19; 109 and 110 are unused since Phase 19 dropped the org app), rows 111 to 120 for the fast redeploy (Phase 20), rows 121 to 125 for Phase 19b's Insights app, rows 136 to 145 for T4, the PostgreSQL flexible server (Phase 24, [ADR 0019](adr/0019-t4-postgresql-flexible-server.md)), and rows 160 to 169 for Phase 28's one command and guided stop ([ADR 0018](adr/0018-fast-redeploy-parallel-tracks-golden-snapshot.md#amendments-2026-10-29-phase-28-one-command-one-guided-stop)). **Revision 2 changes are marked (R2).**

## Classes

| Class | Meaning |
|---|---|
| **FA**: Fully automated | Runs with no human step under the documented minimum permissions (Contributor on the subscription) |
| **AP**: Automated with prerequisite | Automated once a listed prerequisite (P1–P11) or input is in place |
| **MAN**: Manual | No supported automation exists. The repo validates the result and prints exact steps. |
| **OPT**: Optional preview | A preview capability that is opt-in, presenter-driven, or validated empirically |
| **DEF**: Unsupported or deferred | Not supported by the docs, or deliberately out of scope for v1 |

**P** marks a preview dependency. Prerequisites P1–P11 are defined in [ADR 0008](adr/0008-identity-rbac-abac.md) and [prerequisites](prerequisites.md). Validation statuses are defined in [ADR 0012](adr/0012-validation-model.md).

## What stays manual, and why

Every manual step reports **Manual action required** with its exact steps, so nothing is hidden. The first group exists only because no supported automation was found; the others are deliberate.

**No supported automation found** (checked against Microsoft Learn, 2026-10-19 to 2026-10-21):

|---|---|---|---|
| The T2 setup-wizard step, with **Use Azure Login** and never a service principal secret: since Phase 28, a guided stop of about 10 minutes in `deploy.ps1`'s run (choose pay-as-you-go and Standard in the pre-filled setup, and sign in to Azure) | 15a, 161 | Pay-as-you-go SQL Server without a product key is documented only in the [installation wizard](https://learn.microsoft.com/sql/database-engine/install-windows/install-sql-server-from-the-installation-wizard-setup); the [command-prompt reference](https://learn.microsoft.com/sql/database-engine/install-windows/install-sql-server-from-the-command-prompt) has no such option (rechecked 2026-10-29). `ProductKey` mode (P10) is fully unattended with Hub Performance, and `Developer` mode is unattended but Estate only | [Deployment](deployment.md#the-guided-stop-paygwizard) |

**By design: a person approves** (the brief requires human approval before any action):

- Every action the Database Agent or Copilot proposes (row 35).
- The missing-index remediation script (row 75); `reset --undo-remediation` reverts it.

**By design: you sign in** (a repository rule, so no script holds or requests your credentials):

- Signing in to the Azure CLI, once, with `az login` (`--use-device-code` in a codespace or a container). The scripts never sign in, never sign out, and never change the CLI's default subscription: every Azure call names the configured subscription, and the subscription guard checks that subscription's tenant and account before anything is written ([prerequisites](prerequisites.md#target-subscription-configuration-the-subscription-guard)). `init.ps1` then writes the configuration from that sign-in (row 150). On a shared machine, the optional separate Azure CLI profile is also yours to set ([prerequisites](prerequisites.md#optional-a-separate-azure-cli-profile)).
- At the `PaygWizard` guided stop (row 161): the Bastion sign-in to `archost01`, and setup's **Use Azure Login** in the guest, with your own account. No assistant should do these sign-ins for you; the run prints `HUMAN ACTION REQUIRED: DEPLOY.T2.GUIDEDSTOP` for one to relay, and `ProductKey` mode needs neither.
- Signing in the Rayfin CLI, once, as the demo's Fabric user (P14, row 124), for the optional Insights app. Without `-SignIn`, `configure-fabric-app.ps1` only reads the sign-in with `rayfin login status --json` and reports **Manual action required** with the exact command when it's missing; with `-SignIn`, it runs that command in your console and you sign in in the browser (row 152). The CLI's service principal sign-in isn't supported yet ([CLI reference](https://learn.microsoft.com/fabric/apps/cli-reference)). `deploy.ps1` ends **DONE** without the app and lists how to add it.

**Needs someone with more than Contributor** (the scripts print the exact commands, and `assignRoles` runs them when the caller can):

- Contributor for the GitHub identity (P7), Reader for presenters who aren't Contributors (P8), and the opt-in Key Vault's roles (row 98) ([permissions](permissions.md)).
- The on-demand activity control's custom role and its assignments A1-A3 (P15, row 127): only `setup-activity-control.ps1 -GrantRole`, run by an Owner, creates them ([permissions](permissions.md#the-on-demand-activity-control)).
- Resuming or pausing the Fabric capacity (P5): its administrator's decision, outside the demo's resource group ([cost management](cost-management.md#microsoft-fabric-capacity)). For an F capacity that's yours alone, in the same subscription, `fabric.manageCapacity` lets `start-demo.ps1` resume it and `stop-demo.ps1` pause what it resumed, with Contributor (row 153).

**Manual by choice:**

- Sharing the history report with viewers outside the workspace, and their data access for its Direct Lake model (row 108): both grant permissions to people, and workspace members need neither ([history report](../fabric/powerbi/README.md#sharing-the-report)). Phase 19 creates no app; the demo's Fabric app, a Fabric Apps (preview) item built with the Rayfin SDK and CLI, is a separate item (Phase 19b).
- GitHub environments, their secrets, and protection rules (row 46), unless you opt in: with your own GitHub CLI sign-in, `setup-github-oidc.ps1 -ConfigureGitHub` sets them up. Without it, the scripts never write to your GitHub repository, and they print the `gh` commands instead (R283).
