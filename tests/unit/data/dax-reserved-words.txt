# Names a DAX variable (VAR) can't take, for tests/unit/Fabric.PowerBI.Tests.ps1: one a line, in upper case; a line
# that starts with # is a comment. Learn's VAR page says "Reserved keywords aren't allowed" without listing them
# (https://learn.microsoft.com/dax/var-dax), so this list holds every name below, all checked on 2026-11-22. Not every
# function name is reserved, but none of them names a variable here.
# - Every DAX function whose name has no dot, from the DAX reference's contents
#   (https://learn.microsoft.com/dax/dax-function-reference); a name with a dot, such as BETA.DIST, can't be a
#   variable's. And the visual calculations' functions and their axis and reset keywords, from COLLAPSE to
#   LOWESTPARENT (https://learn.microsoft.com/power-bi/transform-model/desktop-visual-calculations-overview).
# - The DAX query keywords EVALUATE, ORDER BY, START AT, DEFINE, MEASURE, VAR, TABLE, and COLUMN
#   (https://learn.microsoft.com/dax/dax-queries), VAR's RETURN, the operators IN and NOT
#   (https://learn.microsoft.com/dax/dax-operator-reference), and the window functions' ABS, REL, DEFAULT, SKIP,
#   DENSE, ASC, and DESC (https://learn.microsoft.com/dax/window-function-dax, https://learn.microsoft.com/dax/rank-function-dax).
# - User-defined functions' keyword FUNCTION and their type hints, from AnyVal to expr
#   (https://learn.microsoft.com/dax/best-practices/dax-user-defined-functions).
# - Analysis Services' MDX reserved words (https://learn.microsoft.com/sql/mdx/mdx-reserved-words): the DAX syntax
#   page says a table's name can't be an Analysis Services reserved keyword
#   (https://learn.microsoft.com/dax/dax-syntax-reference#reserved-keywords).
# - UNDER: the engine refused it as a variable's name live (2026-11-22: "The syntax for 'Under' is incorrect"), though
#   no Learn list has it.
